# 广东美食协同过滤推荐系统

> 基于 Python + Flask 的广东美食智能推荐系统毕业设计

## 项目简介

本系统是一个面向广东特色美食的智能推荐平台，实现 **User-CF 与 Item-CF 两套协同过滤算法**，并引入**偏置项（μ + b_u + b_i）与相似度收缩**改进预测精度；同时提供随机、热门两条基线用于对照实验。系统提供用户、商家、管理员三类角色，覆盖美食浏览、评分、点赞、收藏、评论、举报等完整交互，并内置离线评估模块（Precision@N / Recall@N / NDCG@N / 覆盖率 + MAE/RMSE），可在页面直接对比四种策略的效果。

## 技术栈

| 类别 | 技术 |

## 核心功能

### 用户端
- 注册 / 登录 / 退出（含商家注册，密码加密存储）
- 首页浏览、关键词搜索、分类筛选
- 美食详情、评分（1-5 星）、点赞、收藏、评论
- 浏览记录、个人中心、过敏/忌口设置、黑名单管理、我的举报

### 商家端
- 商家注册（需管理员审核）
- 数据看板（ECharts 柱状图：本店美食评分 + 点赞排行）
- 美食上传、编辑、下架

### 管理员端
- 数据看板（ECharts 饼图/柱状图/折线图）
- 商家审核、美食审核、用户管理
- 举报管理（含处理弹窗与处理说明）

### 推荐算法
- User-CF / Item-CF 双算法，皮尔逊相关（共现去均值）+ 偏置项 + 相似度收缩
- 冷启动（新用户评分不足时热门美食兜底）
- 过敏强制过滤、忌口主动标注、黑名单双维度过滤
- 离线评估：按用户分层留出法（20%），Precision@N / Recall@N / NDCG@N / 覆盖率 + MAE/RMSE
- 对照组：随机推荐、热门推荐，评估页可直接对比四种策略与不同 K 值

> 论文中的实验结果即基于该数据集（204 用户 / 74 菜品 / 5075 条评分，矩阵密度 33.6%）。

## 推荐算法说明

### 算法设计

| 环节 | 做法 | 原因 |
|------|------|------|
| 相似度 | 共现项去均值后的皮尔逊相关 | 直接对原始评分做余弦，会把「打分宽松」误判成「口味相似」 |
| 相似度收缩 | `sim × n / (n + 6)` | 只共同评过 1 道菜就判高度相似，噪声太大 |
| 预测模型 | `b_ui = μ + b_u + b_i`，协同过滤只拟合残差 | 先解释「用户宽严」和「菜品质量」，避免预测值挤在同一档 |
| 邻域筛选 | 每行只保留 Top-K 相似邻居 | K 值可比，控制噪声传播 |
| 冷启动 | 评分 < 2 条时走热门兜底 | 与业务逻辑一致 |

### 离线评估方法

- **划分**：按用户分层留出法，每个用户随机留出 20% 评分作为测试集（评分 ≥ 5 条的用户才参与）
- **相关性判定**：测试集中评分 ≥ 4 视为「喜欢」
- **Top-N 指标**：Precision@10、Recall@10、NDCG@10、覆盖率
- **回归指标**：MAE、RMSE（预测用户会打几分）
- **对照组**：随机推荐、热门推荐（贝叶斯平均）

### 实验结果（204 用户 / 74 菜品 / 5075 条评分，Top-10，协同过滤取 K=5）

| 策略 | Precision@10 | Recall@10 | NDCG@10 | 覆盖率 |
|------|--------------|-----------|---------|--------|
| 随机推荐 | 0.0557 | 0.1750 | 0.1245 | 1.0000 |
| 热门推荐 | 0.0938 | 0.3080 | 0.1985 | 0.2838 |
| User-CF | 0.1067 | 0.3573 | 0.2249 | 0.8919 |
| **Item-CF** | **0.1211** | **0.3784** | **0.2757** | 1.0000 |

- 两个协同过滤算法均显著优于随机与热门基线，Item-CF 在小样本、物品数适中时表现最好
- 热门推荐覆盖率仅 28%，流量集中在少数菜品；协同过滤有效扩展了长尾曝光
- 评分预测：User-CF 在 K=5 时 MAE = 0.6265，K=20 时降至 0.5510，RMSE 0.7924 → 0.6943
